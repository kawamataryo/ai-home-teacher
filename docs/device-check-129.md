# 実機確認：長男がキャラを選び、会いたくなるかを見る（#129）

テストでは測れない「愛嬌」を、実際に子どもが選んで確かめる。

## iPad に入れる

1. 最新の main を手元に持ってくる

   ```sh
   git switch main && git pull
   ```

2. プロジェクトを作る

   ```sh
   cd ios && xcodegen generate && open HomeTeacher.xcodeproj
   ```

3. Xcode で実行先を iPad にして、Run（⌘R）で入れる
4. 初めての画面を確かめたいときは、入れる前に iPad のアプリを消す。そうすると、許可の案内のあとに選ぶ画面が開く
   - 消しても、勉強の記録はサーバーから戻る。記憶も戻る

## 子どもに渡す

説明しないで渡す。選ぶ画面が出ていなければ、右上の人のボタンから開く。

- 動いているキャラに触ると、その声で自己紹介する
- 「〇〇にする」で選ぶ。次の勉強からそのキャラになる
- 勉強を始めて、話しかけて、問題を見せて、ふり返りまで 1 回通す

## 子どもの様子のチェックリスト

- [ ] 説明なしでキャラ選びの画面を操作できる
- [ ] 自分からキャラに触ったり、自己紹介を聞いたりする
- [ ] どのキャラを選び、なぜ選んだか（本人の言葉で）
- [ ] 笑った、話しかけた、真似をした場面があるか
- [ ] 勉強中に、キャラの動きで気が散っていないか
- [ ] 右下の小さな表示でも、キャラの表情が読めるか
- [ ] 声が聞き取りやすいか、声とキャラが合っているか
- [ ] 次の日も同じキャラを選びたがるか

## 大人が確かめること（Simulator では分からなかったこと）

### 速さ

- [ ] 選ぶ画面で 8 人が動いていても、カクカクしない。本体が熱くなりすぎない
- [ ] ムニ、ポン、ノアのセッションで、体のはずみと口パクが滑らか（3 万三角形台、1024px のテクスチャ 3 枚）
- [ ] リカ、ボルの表示が滑らか
- [ ] 読み込みの間が気にならない（選ぶ画面を開いてから全員が出るまで）
- [ ] 環境光が iPad でも効いている。ボルの金属が黒くならない（Simulator のログに `EnvironmentResource with no skybox texture` の警告が出る）

### 声（Simulator の開発者は耳で聞いていない）

- [ ] 8 人の定型句と自己紹介を並べて聞いて、声がキャラに合っている
- [ ] 1 文の途中や定型句で、別の声が混ざらない。替えた直後も同じ
- [ ] **ハル先生の声を決める。** 今の既定は Azure の女性の声（Nanami）で、お兄さん先生と合っていない。ノア先生とも同じ声になっている。替えるなら `prompts/characters/characters.json` のハルの `voice.azure` を変える（例：`ja-JP-KeitaNeural`。ただしコナ先生と同じになるので、コナも見直す）。同梱の音声がなければ初回に作り直す

### 会話

- [ ] 「ねえソラ」「ねえムニ」など名前で呼んで答える。人の声で呼んで、聞き取りが名前をまちがえない
- [ ] 「ねえ先生」と言っても答える
- [ ] 触った反応で、先生の声や聞き取りが止まらない
- [ ] 待機中の癖が邪魔にならない。18〜42 秒に 1 回が多すぎないか
- [ ] 替えたあとも前回の記憶を話す
- [ ] 親のダッシュボードの見出しは「先生のひとこと」のまま。ソラのときに気になるか

### 似ていないか

- [ ] 各キャラが既存のゲームやアニメのキャラに似ていない（開発者は特徴を並べて目で比べただけ）
