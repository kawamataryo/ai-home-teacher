# 技術調査メモ（2026-11-03）

ネタ詰め（grilling）中にサブエージェントで調べた事実のまとめ。未確認の点は明記。

## Claude API

- リアルタイム音声 / speech-to-speech API は無い。入力はテキスト・画像、出力はテキスト。音声は STT + Claude + TTS で組む（Anthropic の ElevenLabs cookbook あり）
- 画像入力: JPEG/PNG/GIF/WebP（HEIC 非対応）。長辺 ~2048px に縮小して送る
- SSE ストリーミング対応（`content_block_delta` / `text_delta`）
- 公式 Swift SDK 無し。HTTP 直叩き。iOS は App Attest で鍵を埋め込まずに直接呼べる（実機のみ、トークン1時間）
- モデル: 低遅延 `claude-haiku-5-5` / バランス `claude-sonnet-5-5` / 高品質 `claude-opus-5-5`
- structured outputs: tool に `strict: true` で入力が schema 準拠。`eager_input_streaming: true` で tool 入力を逐次受信（途中 JSON は寛容パーサが必要）

## 音声ハーネス（GPT Live 相当を Claude で）

- OpenAI Realtime のターン検出: `server_vad`（無音）/ `semantic_vad`（発話終了を分類、`eagerness`）
  - https://developers.openai.com/api/docs/guides/realtime-vad
- 割り込み: ユーザー発話検知で応答キャンセル → 実際に再生された位置まで履歴を切り詰め（`conversation.item.truncate`）
  - https://developers.openai.com/api/docs/guides/realtime-conversations
- OpenAI Agents SDK の VoicePipeline（STT→LLM→TTS）は割り込み非対応。発話中はマイクをミュートが推奨
- Claude での再現: 割り込み時に Claude のストリームを中断し、assistant メッセージを「実際に再生された文字位置」で切る。位置は ElevenLabs の alignment で特定可能（推論）
- OSS: Pipecat（Anthropic 公式対応、iOS SDK あり）、LiveKit Agents（Anthropic プラグイン、Swift SDK、日本語対応の意味的ターン検出）。どちらもサーバー側パイプライン前提
- iOS ネイティブ
  - SpeechAnalyzer / SpeechTranscriber（iOS 26、端末内）。日本語対応は Apple 公式一覧で未確認 → 実機で `supportedLocales` を確認
  - VAD: `SpeechDetector`（iOS 26）
  - エコーキャンセル: AVAudioEngine で `inputNode.setVoiceProcessingEnabled(true)`、入力と再生を同じエンジンに通す。シミュレータでは検証不可
- 日本語 TTS
  - ElevenLabs Flash v2.5: ~75ms、日本語対応、WebSocket で文字単位タイミング（`alignment`）→ 口パクに使える
  - OpenAI gpt-4o-mini-tts: 2027-01-06 提供終了予定
  - Azure: viseme ID あり（ja-JP の対応は要確認）
  - AVSpeechSynthesizer: 単語範囲のみ、viseme なし
- 遅延の目安: 合計 ~800ms。終話判定が大きい。文・節単位で TTS に流すのが定石

## Claude Code の長時間自律実行

- `/goal <完了条件>`: 条件を満たすまで自動でターンを続ける。判定役の小モデルは会話に出た内容しか見られないので、確認できる形の条件にする。上限は「または N ターンで止める」と書く
  - https://code.claude.com/docs/en/goal.md
- auto mode と組み合わせて無人で回す。issue ごとに worktree
- 公式の4条件: ゴールや仕様 / 自分の作業を検証する手段 / 触ってよい範囲 / 止まる条件
  - https://code.claude.com/docs/en/best-practices.md

## Generative UI

- SwiftUI でそのまま使える成熟フレームワークは無い
  - Vercel AI SDK UI: React 系、JS サーバー前提
  - Vercel json-render（実験的）: カタログ＋JSON spec の考え方。Swift 移植 json-render-swift はコミュニティ製
  - Google A2UI: v0.9.1、SwiftUI renderer は未公開。コミュニティ製 a2ui-swift（MIT、pre-1.0）
  - Thesys C1: ホスト型 API
  - AG-UI / CopilotKit: サーバー前提
  - MCP Apps: アプリを MCP ホストにする必要があり重い
- 推奨: Claude の strict tool use で独自コンポーネント（数直線・面積図・ステップカード・グラフ等 5〜8種）を指定 → SwiftUI で描画。表現できないものは `render_svg` tool で自己完結 SVG/HTML を WKWebView に表示

## TypeSafe AI「Jev」/ Decision API

- 文章を生成せず「判断」だけする決定モデル。1つの `state`（テキスト＋画像、画像は実験的）に対して、型付きの質問を複数まとめて投げる
  - `choice`（選択肢から1つ＋確率）/ `score`（段階評価）/ `boolean`（真の確率）/ `box`（画像内の位置）
  - `POST /v1/systemone`、モデル `jev-latest` 等。1回あたり ~$0.00001 程度（Vercel のサンプル値）
  - https://typesafe.ai / https://docs.typesafe.ai/introduction
- Vercel AI Gateway の Decision API 経由でも呼べる（低確信時に他モデルへフォールバック）
  - https://vercel.com/docs/ai-gateway/modalities/decision
- TS ラッパー: Vercel AI SDK `experimental_decide`（`@ai-sdk/typesafe-ai`）、TanStack AI `decide()`
- Swift からは JSON POST で呼べるが、鍵は中継サーバーに置く
- 速度のベンチマーク・レート制限は未確認

## 先生アバター

- 9〜11歳は人間に近すぎるキャラを不気味に感じやすい → 2D キャラが安全
- Rive: SwiftUI runtime（MIT）、ステートマシン、口形状は数値入力で切替（Duolingo と同方式）。Free はスプラッシュあり、Cadet $17/月で消える
- Live2D: 表現力最高。個人・小規模（年商1,000万円未満）は無料。C++/Metal ブリッジが必要、Apple Silicon シミュレータ非対応の報告
- VRM: VRMKit（MIT、RealityKit は iOS 18+）。表情 aa/ih/ou/ee/oh が「あいうえお」に対応
- フォトリアル（HeyGen/Tavus/Simli/Anam）: 分課金、iOS SDK・日本語対応が未確認、子どもの映像をクラウドに送る → 不採用寄り
- 口パク: ElevenLabs の文字タイミング → 母音（あいうえお）＋「ん」の5〜6口形状。予備に音量（RMS）ベース
