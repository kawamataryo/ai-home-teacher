# Lessons

ユーザーから受けた修正と、そこから得たルールを記録する。

- 2026-11-03: TTS の月額を「数千円」と過大に見積もった。実際は月15万字で ElevenLabs 約900円。→ 費用の見積もりは単価と使用量から計算してから伝える
- 2026-11-03: `git add -A` でサブエージェントの worktree（.claude/worktrees/）を gitlink としてコミットしてしまった。→ `.claude/worktrees/` を .gitignore に入れておく。add の前に `git status --short` を確認する
- 2026-11-03: 並行するサブエージェントが同じ名前の型やファイルを別々に作り、マージ時にビルドが壊れた（JSONValue, ProblemKind）。→ 並行作業の前に共通の型（Shared/）を先に決めて brief に書く。マージ前に重複する型名・ファイル名を検出する
- 2026-11-03: squash マージ後、上に積んだブランチに「追加して削除した」ファイルが残った。→ 積み上げ PR は main を取り込んだあと、main との差分に想定外のファイルがないか確認する
- 2026-11-03: サブエージェントの PR 本文の `Closes #N` が誤っていて issue が閉じなかった。→ マージ後に issue の状態を必ず確認する
- 2026-11-03: モックのテストは通るのに本番の API で 400 になる不具合が続いた（tool_choice の強制非対応、strict スキーマの grammar 過大）。→ API の形を変えたら、本番に最低1回当てて確かめる（評価スクリプトか自己テスト）
- 2026-11-03: Haiku が既定で thinking し、返事が遅く、max_tokens を使い切ると空になった。→ 速さが要る会話では thinking を明示的に止め、品質は評価で確かめる。thinking を止めると安全の判断が雑になったので、返事の形をプロンプトに明記した
- 2026-11-03: 1Password の SSH 署名・SSH push が承認待ちで止まり、バックグラウンドのコミットが固まった。→ コミットは `-c commit.gpgsign=false`、push は HTTPS（gh の認証）で行い、git をバックグラウンドで動かさない
- 2026-11-03: プロンプトの例文（「昨日の〜」）をモデルがそのまま使った。→ 例文の可変部分は〈いつ〉のように置き換え、どこから値を取るかを書く
- 2026-11-03: `git merge` のマージコミットも署名が必要で、署名に失敗すると取り込みが確定しないまま（MERGE_HEAD が残ったまま）次の作業に進んでいた。→ マージも `-c commit.gpgsign=false` で行い、`git rev-parse -q --verify MERGE_HEAD` で確定したか確かめる
- 2026-11-04: 「完了条件を満たした」と言いながら、ユーザーが途中で頼んだこと（自由に描ける黒板）を次の提案に回し、シミュレーターを回す確認も代わりの方法で済ませていた。→ 途中で増えた依頼もその場で片付ける。代わりの確認をしたら、本来の確認ができるようになった時点でやり直す。時間に依存するテストの失敗は「関係ない」で終わらせず直す
- 2026-11-06: ローカルの main が古いまま、そこを前提に調べていた（origin は 17 コミット先だった）。→ 作業を始める前に `git fetch` して、`origin/main` から worktree を切ってから読む
- 2026-11-06: `xcodebuild` の出力を grep で絞っていて `** TEST FAILED **` を見落としたまま、PR の本文に「すべて通過」と書いた（テストのホストが起動前に kill されていた）。→ PR を書く前に `Test run with N tests ... passed` と `TEST SUCCEEDED` の両方を確かめる。失敗に理由の行がなければ xcresult を読む
- 2026-11-06: シミュレーターが 2 台起動していて（別のセッションが使っていた）、`simctl ... booted` がどちらを指すかわからなくなった。→ `simctl` と `-destination` には UDID を指定する
- 2026-11-06: 別のセッションが同じ Simulator に別のビルドを入れていて、テストが他のブランチのアプリで動いた（知らないツール名で失敗した）。→ 長い作業では自分専用の Simulator を作る。おかしな失敗はまず実行している物を疑う
- 2026-11-06: 並行してマージされた変更で、プロンプト全体を比べるゴールデンが main で落ちた。→ ゴールデンは自分が守りたい部分だけを比べる。マージの前に main が動いていないか確かめる
- 2026-11-06: Blender の `shape_key_add` の既定（`from_mix=True`）で関係のない頂点が動き、目を閉じると口が縦に伸びた。→ `from_mix=False` にし、動いた頂点をスクリプトで確かめる。テストが通っても画面を見て見つける
- 2026-11-07: Blender の Alpha に値を入れても USD では opacity = 1 のままで、レンズが不透明だった。→ 書き出したものを usdcat で確かめる。透明はアルファのある画像をつなぐ
- 2026-11-07: 選ぶ画面でハルの明るさが起動ごとに変わった。自分の光の変更が原因だと決めつけず、光なしでも再現するかを同じ条件で複数回測って切り分けた。→ 見た目の比較は 1 回のスクリーンショットで判断しない。起動を何回か繰り返して色の値で比べる
- 2026-11-07: 深刻な相談で、要確認のフラグは毎回立つのに親に話すよう勧める言葉が抜けることがあった。1 回の評価の PASS では見えず、くり返して初めて分かった。→ 安全の評価は 1 回で判断せず、くり返して数える。プロンプトで直らないものは仕組みで直す
- 2026-11-07: テクスチャをコミットしていないので、clone 直後の `.blend` を開くと質感が欠けていた。手元では画像があるので気づかず、元データを別の場所で開いて分かった。→ 元データは何もない状態で開いて確かめる。画像は `.blend` に入れる
- 2026-11-07: 選ぶ画面を「テストが通って選べる」で完了にしていて、「作り込んでいる？」と聞かれた。issue の「カタログの一覧ではなく、会って選ぶ体験」を満たしていなかった。→ 画面の issue は機能の完了条件だけで閉じない。概要に書かれた体験と見比べて、スクリーンショットで自分に問い直す
- 2026-11-07: Python の置換で 2 つのパターンのうち先に当たった方が残り、新しい関数を画面から呼んでいないのに「直した」と思った。→ 直した関数を呼んでいるかを grep で確かめ、見た目は直した後のスクリーンショットで確かめる
